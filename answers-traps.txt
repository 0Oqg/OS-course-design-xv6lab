1. 哪些寄存器用于保存函数参数？main 调用 printf 时，13 保存在哪个寄存器中？

RISC-V 使用 a0 到 a7 寄存器传递函数的前八个整数或指针参数。
在下面的函数调用中：
printf("%d %d\n", f(8)+1, 13);
a0 保存格式字符串的地址；
a1 保存 f(8)+1 的结果，即 12；
a2 保存整数 13。
从汇编代码也可以看到：
24:  li  a2,13
26:  li  a1,12
因此，13 保存在 a2 寄存器中。


2. main 的汇编代码在哪里调用了函数 f？函数 f 又在哪里调用了函数 g？

main 中没有真正调用函数 f，函数 f 中也没有真正调用函数 g。
虽然 call.asm 中仍然保留了 f 和 g 的函数代码，但 main 在执行时没有使用 jal 或 jalr 指令调用它们。
这是因为编译器进行了内联优化和常量计算：
g(8) = 8 + 3 = 11
f(8) = g(8) = 11
f(8) + 1 = 12
所以编译器直接生成了：
26:  li  a1,12
即直接把计算结果 12 放入 a1，而没有实际调用 f 和 g。


3. printf 函数位于什么地址？

根据 call.asm：
0000000000000628 <printf>:
因此，printf 函数的地址为：
0x628


4. main 中执行调用 printf 的 jalr 指令后，ra 寄存器的值是多少？

调用 printf 的相关汇编代码为：
30:  auipc ra,0x0
34:  jalr  1528(ra)  # 628 <printf>
38:  li    a0,0
jalr 指令会把下一条指令的地址，即当前 jalr 指令地址加 4，保存到 ra 寄存器中。
jalr 指令位于地址 0x34，因此：
ra = 0x34 + 4
ra = 0x38
所以，执行 jalr 指令后，ra 寄存器的值是 0x38。


5. 下面的程序会输出什么？如果 RISC-V 是大端机器，应如何修改 i？是否需要修改 57616？

unsigned int i = 0x00646c72;
printf("H%x Wo%s", 57616, &i);
十进制数 57616 的十六进制表示是 e110。
RISC-V 是小端机器，因此整数 0x00646c72 在内存中按照从低地址到高地址排列为：
0x72 0x6c 0x64 0x00
这些字节对应的 ASCII 字符分别是：
'r' 'l' 'd' '\0'
因此程序输出：
He110 World
如果 RISC-V 是大端机器，为了让内存中的字节顺序仍然是：
0x72 0x6c 0x64 0x00
应该把 i 设置为：
unsigned int i = 0x726c6400;
不需要修改 57616，因为大小端只影响数据在内存中的字节排列，不会改变整数本身的数值。57616 使用 %x 输出时仍然是 e110。


6. 下面的代码中，y= 后面会输出什么？为什么？

printf("x=%d y=%d", 3);
x= 后面会正确输出 3。
但是 y= 后面的值是不确定的，不能给出一个固定结果。它可能是之前残留在寄存器中的任意值。
格式字符串中包含两个 %d，因此 printf 需要两个整数参数。程序实际上只提供了一个整数参数 3。
第一个整数参数 3 保存在 a1 中，而 printf 在处理第二个 %d 时会继续读取 a2 寄存器。由于程序没有为 a2 提供对应参数，a2 中的内容是不确定的。
因此，这段程序属于未定义行为，y= 后面的输出值无法确定。
